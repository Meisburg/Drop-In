## 2. The four code hazards — all REAL, all still present

The handoff listed these as "found by inspection, not yet fixed," with line
numbers. **Line numbers have drifted** (`db.ts` is now 6,616 lines, not the
~1,400 the handoff implies). Located here **by content**, which is what a builder
should trust:

| # | Handoff's line | **Actual current site** | Status |
|---|---|---|---|
| 1 | `db.ts:317` | `src/lib/db.ts:324` — `redirectTo: oauthRedirectTo(window.location.origin)` | ⚠️ **present** |
| 2 | `db.ts:1352` | `src/lib/db.ts:1377` — `redirectTo: resetRedirectTo(window.location.origin)` | ⚠️ **present** |
| 3 | `db.ts:1339` | `src/lib/db.ts:1364` — `buildShareUrl(playdateId, import.meta.env.VITE_PUBLIC_BASE_URL ?? '', window.location.origin)`; pure fn at `src/lib/trust.ts:252` | ⚠️ **present** |
| 4 | `email.ts:40` | `src/lib/email.ts:40` — `return import.meta.env.VITE_PUBLIC_BASE_URL ?? window.location.origin` | ⚠️ **present**, line still exact |

**Every one of the four is the same root cause:** the app falls back to
`window.location.origin` when `VITE_PUBLIC_BASE_URL` is unset. In a Capacitor
shell the origin is `capacitor://localhost` (iOS) or `https://localhost`
(Android) — not a URL the auth provider, an email client, or a recipient can use.

### Good news the handoff did not have

**Two of the four already have a seam, and it is the right shape.** The OAuth and
reset paths do not inline the origin — they call pure helpers:

- `src/lib/oauth.ts:65` — `oauthRedirectTo(origin)` → `${origin}/`
- `src/lib/passwordReset.ts:29` — `resetRedirectTo(origin)` → `${origin}${RESET_PATH}`

Both are **pure functions with sibling tests**, exactly per the build law. So the
fix is not "rearchitect four call sites." It is:

1. **one decision** — what is the canonical public URL inside the shell? — and
2. **one small seam change** at each site so the shell passes a configured
   absolute base instead of reading the origin.

`VITE_PUBLIC_BASE_URL` is *already* the intended mechanism (it is documented as
winning over the origin in `email.ts:35` and `trust.ts:248`). **Verify it is
actually set in the Vercel production environment** — if it is, hazards 3 and 4
may already be correct in production and only wrong in the shell.

**Recommendation:** make the slice-1 fix "the shell sets an absolute base URL at
build time and every origin fallback is provably unused under it," with a test
that asserts a `capacitor://` origin never reaches a redirect or a share link.
That is a bounded, testable change — not a refactor.
