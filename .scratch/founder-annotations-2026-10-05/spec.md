# The founder's 2026-10-05 live annotations — inventory and status

**What this is.** On 2026-10-05 the founder gave feedback two ways: in the DSH chat
and through the **impeccable live tool**, which pins each note to the exact element
he was looking at. This file is the inventory of the SECOND channel, with each
item's status measured against this tree. `source-annotations.json` beside it is
the raw export, committed so the words outlive the machine.

⚠️ **The exporter itself is NOT committed, deliberately**: `.scratch/*.mjs` is on
this repo's gitignore (the local-artifact rule in `docs/agents/auto-push.md`), so
`export.mjs` lives here as a local tool only. The export is regenerated by reading
every `event.freeformPrompt` out of `.impeccable/live/sessions/*.jsonl` and deduping
on (prompt, pageUrl, element.anchor) — the tool logs one annotation up to three
times. `source-annotations.json` carries `exportedAt` and the record count, so a
stale copy is visible.

**Why it exists.** Four reasons, all of them things that have already gone wrong
in this repo:

1. The live annotations are stored in `.impeccable/live/sessions/*.jsonl`, which is
   **untracked and machine-local**. task-state.md records the cost of that:
   *"the three earlier annotation batches (V13/V21/V24) cite exports that are not
   in the repo, which is how a live moderator tool came to appear in no markdown
   anywhere."* This export is committed for the same reason V30 committed its own.
2. The handover prompt that opened this session traced most of its items to "the
   founder reported" — and for one item it **paraphrased him into the wrong
   feature** (see item 16's note and `.scratch/first-run-tooltip-target/spec.md`).
   A committed source makes that failure impossible to repeat.
3. Two items below are **OPEN and were NOT in the handover at all** (items 3 and
   4). They are found here only because the annotation channel was read.
4. Three annotations are impeccable COMMANDS (`clarify`, `distill`, "what would
   you recommend") rather than feedback; they are kept in the export because they
   are what produced the v30-3 filter-pill work, and labelled as commands here.

**Method.** `.impeccable/live/sessions/*.jsonl` → every `event.freeformPrompt`,
deduped on (prompt, page, element) because the tool logs one annotation up to three
times. **19 exported records, 16 of them feedback** — the other three are impeccable
COMMANDS (`clarify`, `distill`, "what would you recommend"), grouped into row 6.
Status was measured by reading the code, not by asking the tool.

## ⚠️ Item 3 is the one item nobody has closed, and it is a COPY defect

His words, and the element he pinned (`location-device-note`), match
`LocationModal.tsx:383-390`, whose `denied` branch renders
`'Location is off for Drop In. Turn it on in your browser settings, or type an address.'`
(`:203`).

Two things follow, and they are measured rather than argued:

- **The string has not changed since before his annotation.** `git log -S "Location
  is off for Drop In" -- src/components/LocationModal.tsx` returns exactly one
  commit, `1459b79` (V28 r4), which predates 15:24. So nothing has answered him.
- **His misreading is the copy's fault, not his.** The sentence opens *"Location is
  off for Drop In"*, which reads as a setting OF THE APP. It is the browser's
  per-site permission, and the second half of his note — *"I also don't see in the
  settings where you turn it off or on"* — is the natural next move for someone who
  has just been told that. The note does say "in your browser settings", and he
  still read it as the app's, which is the evidence that naming the browser once,
  in a subordinate clause, is not enough.

**The fix is one string plus a sibling test, ~15 minutes**, and it is NOT in the
handover's list:

> *"Drop In isn't allowed to use your location — that permission lives in your
> browser, not in Drop In's settings. Allow it there, or type an address."*

⚠️ **AND THERE ARE TWO COPIES OF THE OFFENDING SENTENCE, which is the one-copy rule
firing on a string rather than a function.** Measured: `LocationModal.tsx:203`
(*"Location is off for Drop In. Turn it on in your browser settings, or type an
address."*) and `OnboardingPage.tsx:1196` (*"Location is off for Drop In. Type your
address instead, or turn it on in your browser settings."*) — the same claim with
the clauses swapped, which is what two futures looks like one edit apart. So the
fix is a `lib/` const (one module, one sibling test that pins the two properties
below) consumed by both call sites, not two edited strings. Nothing pins either
sentence today: `grep -rn "Location is off for Drop In" src/ e2e/` returns only
those two render sites.

The acceptance criterion that makes it a fix rather than a rewording: the string
must NOT contain the phrase "Location is off for Drop In" (the reading he had), and
it must name the browser as the owner of the permission BEFORE offering the
alternative.

**Status of this item: ready-for-agent, unblocked in CONTENT and BLOCKED IN MECHANICS — and the mechanics are the do-not-touch rule.**

⚠️ **THE FIX IS WRITTEN AND CANNOT LAND YET, for a reason that is not about the
copy.** The canonical strings belong in `src/lib/geolocation.ts` (which already
owns the four named outcomes and has a sibling test), and both call sites must read
them — but **one of the two call sites is `src/components/LocationModal.tsx`,
which is ANOTHER SESSION'S UNCOMMITTED FILE** (it carries that session's "+Use my
location" ripple work; `src/index.css` and `src/pages/FeedPage.tsx` are the other
two). This session's standing rule is *do not touch another session's uncommitted
files*, so the fix was written, verified as ready, and then REVERTED rather than
left as a half-fix that would put the canonical copy on the onboarding screen
while the founder's own surface — the modal's note — still said the thing he
misread. **The moment that file is committed or reverted, this is a 10-minute
change:** add `GEOLOCATION_OUTCOME_COPY` to `src/lib/geolocation.ts` with the
`denied` sentence below (and the other two byte-identical to the modal's, which
are the canonical ones), point `LocationModal.tsx`'s three `setDeviceNote` calls
and `OnboardingPage.tsx`'s three `setLocationNote` calls at it, and add the
properties to `geolocation.test.ts`.

The `denied` sentence, ready to paste:

> `'Drop In isn’t allowed to use your location — that setting lives in your browser, not in Drop In. Allow it there, or type an address.'`

and the test's two properties: the string does NOT contain `Location is off for
